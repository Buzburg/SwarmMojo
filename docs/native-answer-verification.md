# Native fixed-format answers

The direct C/Mojo model path now supports the same bounded answer shape used by project-grounded HTTP chat. `wb_session_answer_format` selects a fixed native grammar before the first prefill: one JSON object containing one nonempty `answer` string, at most 1600 characters. Callers cannot submit arbitrary grammars through this API. The corresponding Mojo operation is `RWKV7Session.answer_format()`.

The grammar filters the actual recurrent model's logits, then selects the highest permitted logit. Sampling remains greedy and session-local. The accepted token advances the grammar only when generation consumes it; buffer-size probes and rejected operations do not advance it. A missing finite candidate, allocation failure after runtime mutation or decode cancellation leaves the affected session unusable. The implementation releases the grammar with its owning session, which continues to retain its model after the caller closes the separate model handle.

Formatted sessions accept one initial prompt. Changing the format or adding a second prefill after that point fails explicitly. Their grammar state is not included in the existing checkpoint layout, so native state-size/export/import operations reject formatted sessions rather than returning an incomplete checkpoint. The existing unformatted state layout and checkpoint operations remain unchanged. Saving formatted conversations still requires sampler-state persistence under T10; this increment does not certify that milestone.

## Actual checks

The C probe uses two real 2.9B model sessions with independent grammar samplers. It compares every generated byte, including after a short-buffer query and a cancel/reset cycle, parses the completed JSON and checks the arithmetic answer `56`. It also verifies early-format requirements, one-prompt limits, explicit checkpoint rejection and an unchanged unrelated plain session. No fixed-answer substitution is present in the adapter.

The compiled Mojo probe independently enables the format and generates the same complete JSON answer. The existing move-only ownership, Unicode input, failure and cancellation binding checks also pass. A C++ fault fixture forces allocation failure during grammar construction and verifies a retry succeeds while the original plain session remains usable.

The separate four-test workshop suite passed with its actual model test enabled, including checkpoint continuation and independent forks. The first combined command omitted that suite's distinct `OMARCHY_STATE_LIBRARY` variable and skipped its real-model case; the subsequent explicit run passed all four. This skip is not counted as model verification.

These are CPU and format/lifecycle checks. They do not establish broad factual accuracy, arbitrary grammar support, GPU cancellation, native broker conversation dispatch or restartable formatted sessions. The installed broker continues to use the previously verified HTTP generation path.
